# 案例引擎（case-engine）

目标：消灭"内容空洞"——每个知识/技能点都有**具体、可核对**的案例支撑。实测教训：案例空泛源于"有背景无过程、讲概念无步骤"，六要素格式强制案例落地。

## 双通道获取

按优先级：
1. **联网检索真实案例**：按知识点/主题搜索行业真实项目、软件官方案例、知名作品、时事案例。
   - 例：讲 AE 特效 → 搜某综艺片头、某广告的实际制作案例；讲数字视觉设计 → 搜 AI 营销案例、知名 IP、影视案例。
   - 检索到的案例必须标注来源，属于"由检索资料整理"的内容一并提示老师核对；案例配图优先真实网图（见 image-engine）。
2. **内置案例模板兜底**：检索不到合适案例时，用下表的学科主题案例框架生成，保证永远有案例可用。

## 结构化案例格式（六要素，强制）

每个案例按以下六段输出（**不含"讲法建议"**）：

```
案例背景            —— 这个案例是什么、发生在什么场景（时间地点主体）
与教学目标的关系     —— 为什么用它来讲这个知识点
实施过程            —— 老师怎么带学生走一遍（分步骤、可操作，≥3 步，每步写"做什么、怎么做"）
成果与数据           —— 最终产出了什么（作品/数据/判决/结果）；无公开数据时写"定性成果，无公开数据"，禁止编造数字
教学点评            —— 好在哪里、容易错在哪、可迁移到什么场景
课堂提问            —— ≥2 个面向学生的问题（可含提示与答案要点）
```

### 关键要求（实测提炼）
- **实施过程必须详细可操作**：至少 3 步，每步写成"做什么、怎么做"（如"① 把角色设定为聪明又贪玩的粉色狐狸，② 通过乐园互动、短视频人设积累粉丝"），禁止"演示该案例"这种空泛写法。
- **成果与数据是可选项**：不是每个案例都有公开数据；有可靠来源才写具体数字（标注"由检索资料整理，请核对"），否则写"定性成果，无公开数据"——**禁止编造数字**。
- 案例必须紧扣该课教学目标，禁止为凑案例而堆砌。
- 每个新知识点至少 1 个案例；重点难点知识点可 2 个（一个讲透 + 一个迁移）。

## 内置案例模板（兜底，按学科主题分类）

| 学科类别 | 案例框架示例 |
|---|---|
| 计算机 / 数字媒体 | 真实项目复盘：某 App/影视/游戏片段 → 拆解技术步骤 → 学生复刻关键步骤 → 对比原作点评 |
| 经济 / 管理 | 知名企业决策案例：背景 → 数据/决策 → 结果 → 与理论模型的对应 → 课堂讨论点 |
| 法律 / 政治 | 典型案例或判例：案情 → 争议焦点 → 判决/依据 → 对概念的印证 → 延伸思考 |
| 语言 / 文学 | 文本细读案例：选段 → 语言特征分析 → 与理论/时代背景关联 → 仿写任务 |
| 理工 / 医学 | 经典实验或事故案例：现象 → 原理推导 → 数据佐证 → 安全/伦理引申 |
| 艺术 / 设计 | 代表作品拆解：作品 → 技法/风格要素 → 步骤演示 → 学生创作任务 |
| 初高中学科 | 生活化情境案例：场景 → 知识关联 → 探究活动 → 结论归纳 |

兜底案例必须在文末标注"示例案例，请老师替换为本地真实案例"。

## 案例标题规范

教案中案例标题：`案例 N（六要素）· 案例名`（如"案例 1（六要素）· 天猫 618『AI 玩拍』"）；渲染时案例名加粗独占一行，六要素各自成段（【案例背景】【与教学目标的关系】【实施过程】【成果与数据】【教学点评】【课堂提问】加粗小标题 + 内容行，①②③ 每项一行）——见 lesson-structures 排版规范。
