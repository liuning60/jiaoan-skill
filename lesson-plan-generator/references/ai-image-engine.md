# AI 教学配图引擎（ai-image-engine）

目标：解决两个实测痛点——① AI 生成图"太难看了"；② 明明选了"网图优先"，成品里还是 95% 生成图。
本文件是 `image-engine.md` 的增强层：先解决"搜不到网图"，再解决"生成图质量差"。两条都必须在每次配图时执行，不能只走其中一条。

> v1.4 升级（grilling 讨论锁定 + cinema-dna 吸收）：吸收 GitHub 生态方法论——`taste-skill@imagegen-frontend-mobile`（反 AI 味 / 可读性 / 重刷判定）、`inference-sh@prompt-engineering`（prompt 结构 / 负面词）、`dacnay816y62-hub/cinema-dna-21x9x3`（反 AI 质感纪律 / 信息密度克制 / 质感基座 / 先事实后美术）。新增硬规则：**prompt 自查 7 项、每图 prompt 随图存档、执行通道永远免费、视觉不强制统一**。

## 0 · 铁律（优先级最高，每次配图必守）

1. **执行通道永远免费**：生图只用豆包 image_gen，**不引入任何付费生图 API / 通道**（如 inference.sh 等需注册 key 的 CLI）。理由：教案生成器的最终用户是老师，他们不会去注册付费生图服务。其他平台按 §4.5 映射表用宿主自带免费生图能力。
2. **视觉不强制统一**：内容 / 知识类型优先级高于视觉统一。不为整本教案"看起来整齐"牺牲内容适配——流程示意、写实案例、界面示意本来就该按各自类型长样子。只在"同一类型内部"保持一致性（示意都扁平、写实都摄影、界面都可读），不跨类型强行统一。
3. **每张生成图三步走**：写详细 prompt → **自查 7 项（§2.4）通过才发出** → 生成后**prompt 与图一起存档（§2.8）**。

## 1 · 网图优先强化（先让"网图优先"真正生效）

"网图优先"失效的根因不是策略错，而是**搜图动作没做对**。按下表自查：

| 失效原因 | 对策 |
|---|---|
| 关键词太宽泛（如只搜"海报设计""VI设计"） | **拆成 2-3 个具体实体关键词并行搜**：从案例里提取可搜实体——作品名、品牌名、软件界面、获奖作品、行业原型。例：讲"VI 设计"→ 并行搜"知名品牌 VI 设计案例"+"某具体品牌 VI 手册" |
| 只搜中文，优质案例图在英文站 | **中英双语各搜一轮**：同一实体用中文和英文各发一次 image_search，取质量高者 |
| 不知道搜什么 | 先从案例六要素的【背景】【实施过程】里提取可搜实体；没有实体的抽象概念直接判定为"应 AI 生成"，不浪费轮次 |
| 搜到图模糊/小/带水印 | 用 `image_short_edge_px ≥ 640` 过滤小图；带水印、模糊、版权存疑的图不采用（现有规则），降级 AI 生成或占位 |
| 类型误判 | 网图只用于四类：**真实案例作品、实物/实拍照片、软件界面截图、地标/品牌 Logo**。流程、原理、结构、对比等抽象示意本来就没有网图，AI 生成是正解——但要主动向用户说明"这类图没有网图来源，采用 AI 示意图" |

**写实图分工（v1.3，按用途决定走网图还是 AI）**：

| 用途 | 通道 | 说明 |
|---|---|---|
| A 案例作品展示（真实海报/品牌实物/获奖作品） | **网图优先** | 真实作品网图最靠谱，AI 写实反而失真；搜不到才降级 AI |
| B 实物/场景示意（印刷品效果、设计工作台、设备、拍摄现场） | **AI 写实生成** | 网图难搜全，AI 可按知识点定制；用详细摄影语言写 prompt（见 §2.5） |
| C 人物氛围（课堂、工作室场景） | 少量点缀 | 不是重点，够用即可，避免每次课都塞人物图 |

执行顺序（每次配图固定）：
1. 从案例提取可搜实体 → 中英双语 image_search（并行，≤3 个 query/轮）
2. 有合格网图 → 采用并标注来源（"公开案例·检索整理，请老师核对"）
3. 无合格网图 → 进入第 2 节 AI 生成（**不是直接放弃，是确认该类型无网图后**）

## 2 · AI 生成质量提升（把"难看"解决掉）

### 2.0 反 AI 味清单（v1.3，吸收 imagegen-frontend-mobile 方法论）

生成任何图之前，先对照此清单检查 prompt 里有没有"AI 味"——**这是"廉价感"（B 痛点）的主要来源，属于主动预防，不是事后补救**：

**视觉雷区（禁止）**
- 紫蓝渐变满天飞（默认创业风渐变）
- 玻璃拟态卡片（无意义的磨砂透明卡片）
- 无意义的环境光斑 / 抽象漂浮球体（ambient blobs）
- 假霓虹高级感、dribbble 风格浮动小组件
- 所有元素超大圆角、过度光滑假质感

**布局雷区（禁止）**
- 假图表堆砌（没有数据意义的柱状图/折线图装饰）
- 重复的统计卡片、一屏塞满 12 个组件抢注意力
- 巨大的空卡片、弱内容的占位块

**文案雷区（禁止）**
- 空洞口号式文字（"解锁潜能""极致体验""焕新你的每一天"等）
- 假品牌词（Acme / NovaCore 之类无意义品牌名）

**质量词克制**：不堆砌 "8K、超写实、masterpiece、best quality" 等通用质量词——堆词本身就是 AI 味；用**具体风格语言**（如"扁平化教学插画，低饱和莫兰迪色，圆角矩形色块"）代替。

**可读性红线（界面/示意图必守）**：文字小于可读即视为失败；宁可减少内容、放大文字，不牺牲可读性。画面文字能不出现就不出现。

### 2.0.1 cinema-dna 反 AI 质感纪律（v1.4 新增，吸收 cinema-dna-21x9x3）

核心理念：**质感来自具体的光线、视角、材质、动作语言，而非形容词、滤镜或堆砌**——"像该有的样子，不像 prompt 在炫耀名词"。

**生图禁用词（写进 prompt 的高风险词，全禁）**
- 通用堆砌词：`rich detail / highly detailed / intricate / epic / dramatic / volumetric / beautiful / masterpiece / hyperreal / 8k / ultra detailed / razor sharp / glossy / polished / sleek / shiny / perfect surface`
- 效果/模板词：`CGI render / Unreal Engine look / game cinematic / concept art / digital painting / vintage filter / cinematic color grading / moody film still`
- 教学场景理解：把"细节丰富、极致细节、史诗感、美丽、杰作、超写实"这类词从 prompt 里删掉，换成具体描述；不写"光滑、抛光、完美表面"。

**信息密度克制（每图一个主线索）**
- 每张图只放 **1 个主要信息 + 至多 1 个次要线索**，其余画面可以留白/简化/弱化，禁止把知识点全部塞进一张图。
- 场景细节 ≤2-3 个（另有主体、风格、光源即可）。
- **更少、更短、更受约束的 prompt 优于长堆砌**：一个主体 + 一个场景 + 一个光源 + 一个风格基座 + ≤3 细节，就够了。

**质感基座（一套图一个质感）**
- 每节配图先选定一个"质感基座"（对应 cinema-dna 的镜头载体）：如**教材印刷质感 / 白板板书风 / 屏幕截图风 / 实拍照片风**，整节同一类型的图共用。
- 质感语言要具体：如"哑光印刷、轻微纸纹、低对比、低饱和"；禁止每张图质感漂移。

**受控不完美（不堆装饰）**
- 一张图只用一个"不完美/纹理家族"（如只有纸纹、或只有轻微颗粒、或只有留白），**禁止组合所有装饰模式**（烟+光斑+颗粒+渐变全上 = AI 味）。
- 所有元素必须有教学理由：前景、装饰、箭头、色块必须服务于信息表达，禁止无意义装饰（与 §2.0 布局雷区一致）。

### 2.1 模型与流程（豆包环境）

- **模型优先：seedream 5.0 Pro（会员）＞ 5.0 flash**。教案配图是交付门面，不省模型额度；5.0 Pro 对"主体清晰、无乱码、风格统一"显著优于 flash。
- 生图前走 doubao-creative-design 轻量流程（三态齐全才可生图）：
  1. `product_route_locked`：锁定产物为"教学示意图"（命中 infographic-design 路由的简化版：结构/流程/对比类）或"案例写实图"；
  2. `clarification_gate_passed`：非视觉信息已确认（每节配几张、什么类型、选项 A/B）——这些在生成前必问项里已收集，无新增阻塞；
  3. `model_rewrite_loaded`：按实际模型读取对应改写规则（4.5 详细维度 / 5.0 Pro 轻改写）后再写 prompt。
- 其他平台：按跨平台映射表替换宿主生图能力，流程与质检标准不变。

### 2.2 教学配图风格映射（按知识类型选风格，禁止"一个风格套所有图"）

| 知识类型 | 推荐风格 | 说明 |
|---|---|---|
| 流程 / 步骤 / 架构 | 扁平化示意图 | 色块+箭头+编号，教学风，信息层级清楚 |
| 抽象概念（色彩、构图、创意方法） | 简约插画 | 主视觉+充足留白，避免花哨堆砌 |
| 真实案例 / 作品 | 写实 / 摄影风 | 优先网图（写实分工 A）；确需生成用写实风 |
| 实物 / 场景 | AI 写实摄影风 | 详细摄影语言，见 §2.5 |
| 软件 / 界面操作 | 干净 UI 扁平示意 | **默认选项 B 截图占位**，见 §2.6 |
| 数据 / 图表 | 简洁图表 | 柱/线/环，避免过度 3D 装饰 |

### 2.3 Prompt 硬约束（教学场景必加）

- 必带："无水印、无logo、无文字水印、无边框、无品牌名"。
- **必带负面词**（吸收 prompt-engineering）：`blurry, distorted, extra limbs, watermark, text, low quality, cartoon, anime`——直接压制畸形（A 痛点）。中文可写"画面清晰、主体完整、无多余肢体、无文字水印、无卡通化"。
- **写实类追加负面词**（吸收 cinema-dna）：`no CGI render, no glossy specular highlights, no oily skin, no waxy faces, no plastic, no over-clean, no game cinematic, no concept art, no digital painting`——压制"AI 油腻/游戏感/棚拍感"（B 痛点）。
- **prompt 密度原则**（吸收 cinema-dna，v1.4）：一个主体 + 一个场景 + 一个光源 + 一个风格基座 + ≤3 个具体细节；**更短、更受约束的 prompt 优于长堆砌**。禁止在 prompt 里写"细节丰富/极致细节/史诗感/杰作/超写实"等堆砌词（见 §2.0.1 禁用词）。
- **画面尽量不出现文字**；必须出现文字时 ≤3 个词，用中文双引号"“指定"，生成后逐字 OCR 核对。
- 结构完整描述：主体 + 场景 + 风格 + 主色调 + 光线/质感；并明说"适合教案/课件插图，简洁清晰，主体突出，留白充足"。
- 不直接引用第三方品牌、影视作品、在世艺术家名做风格锚点（转化为通用风格语言）。
- 禁止 `XX`、`待补充文字` 等让模型自由补字的表达。

### 2.4 Prompt 自查 7 项（发出前必做，用户硬规则）

**每张图的 prompt 写好后、调用生图工具前，必须逐项自查；任何一项不过，改 prompt，不许直接发出。** 7 项：

1. **内容正确性**：画面描述与知识点/案例是否吻合（治"不匹配"）
2. **文字风险**：能不出现文字就避免；必须出现时 ≤3 词、引号指定、写明"无文字乱码"（治乱码）
3. **AI 味扫描**：是否踩了 §2.0 反 AI 味雷区（紫蓝渐变、玻璃卡片、无意义装饰、堆砌"8K 超写实"等）（治廉价感）
4. **负面词已带**：§2.3 负面词是否写全（治畸形）
5. **类型匹配**：知识类型 → 风格映射（§2.2）是否选对（流程→扁平示意、写实案例→摄影、界面→可读 UI）
6. **硬约束齐全**：无水印/无logo/无边框；主体、背景、色调、布局描述完整
7. **存档就绪**：最终确认版 prompt 已写成文字，准备随图保存（§2.8）

### 2.5 写实图 prompt 规则（v1.3 建立，v1.4 吸收 cinema-dna 升级）

B 类图（实物/场景示意）用 AI 写实生成时，prompt 必须带**具体摄影语言**，而不是干巴巴一句"写实的图"——**写实感来自具体的光线、视角、材质、动作，而非形容词**（cinema-dna 核心理念）：

- **相机与镜头感**："标准镜头视角 / 微距 / 广角 / 俯拍 45°"
- **光照**：写"光的来源和方向"而非"氛围感"——"柔和的室内自然光 / 窗边侧光 / 顶光 / 暖色台灯局部光"；光线必须有合理来源，禁止无来源的发光/边缘光
- **材质与细节**：具体材质词（"磨砂塑料""哑光纸""金属拉丝""旧皮革"）；写"磨损、划痕、灰尘、脚印"这类真实痕迹，避免"完美表面"
- **场景锚点**：放在**普通、真实可解释的实景**里（"教室书桌一角""白色背景展示台""校园走廊"），避免"广告棚拍感/明信片式平衡"
- **透视与构图**："居中构图""三分法""留白充足"
- **动作/状态**：写"进行中的动作状态"（如"正在翻页的手""半成品印刷品"），不写摆拍姿态
- 示例骨架：`[主体实物]，[普通实景]，[光源来源与方向]，[材质细节]，[构图]，标准镜头视角，写实摄影风格，适合教案插图，简洁清晰，无水印无文字`

### 2.6 界面图规则（v1.3，全类型覆盖）

教案面向所有学科老师，界面类图必须覆盖**全部类型**：
- 桌面软件界面（Photoshop / AE / Excel，含**理工科专业软件如 CAD、MATLAB、仿真软件**）
- 手机 App 界面
- 网页界面

策略（关键）：
- **默认走界面图选项 B**：留"此处建议插入：XX 截图"占位，由老师补真实截图。**专业软件界面 AI 生成几乎必乱码**（菜单/参数/坐标轴全是文字），假界面误导学生，真截图只能老师自己截。
- 若用户明确选 A（AI 生成）：只生成**干净可读的教学概念示意**——不追求以假乱真，界面要素简化（菜单栏、工具区、画布区三大块），文字能省则省，宁可是"示意图"也不冒充真软件。
- 界面 prompt 通用骨架：`[软件类型]界面教学示意图，左侧工具/导航区，中间主工作区，上方菜单栏，扁平简洁，浅色背景，文字尽量少，无水印无logo，清晰可读`。

### 2.7 生成后质检（每次必做，A+B 分级）

**A 级（硬伤，重刷红线）**——出现即重刷，不留。**先事实，后美术**（吸收 cinema-dna 验收哲学）：内容正确性是硬门槛，再好看的图只要知识点错了就必须重刷，审美不能抵消内容错误：
1. 画面内文字乱码 / 错字（OCR 逐字核对）；
2. 主体畸形（多余手指、结构错乱、部件数量/方向错）；
3. 理工/工程类结构图部件、方向、连接关系错误；
4. 画面与知识点明显不符。

**B 级（廉价感，主动预防）**——不应依赖事后补救，而是靠 §2.0 反 AI 味清单 + §2.0.1 质感纪律 + 具体风格语言在 prompt 层面预防；若生成后仍有明显廉价感（模板感、堆砌感），重刷并加强约束。

**质感自查（v1.4 新增，吸收 cinema-dna V4 自查）**——出现任一信号即返工：
- 每张图都一样"精致/堆满/漂亮"（没有信息主次）；
- 质感基座不可见或每张图质感漂移（应一套图一个质感）；
- 画面像"prompt 插画"而非"教学里该有的样子"（过于炫技）；
- 装饰元素（光效、颗粒、渐变）没有教学理由。

重刷对应数字协议"2 = 图片重新生成"。

### 2.8 Prompt 存档（v1.3，用户硬规则）

**每张生成的图必须配套其详细 prompt，随图一起保存**。目的：可追溯（这图怎么来的）、可复用（别的课借走）、可重刷（原 prompt 改一点再生成）。

格式（建议）：
- 图片文件命名：`lesson{N}_img{M}.jpg`（N=第几节，M=第几张）；
- 同目录生成一个清单文件 `lesson{N}-prompts.md`，记录每张图的：图序号 → 最终确认版完整 prompt → 用途/对应知识点 → 生成时间；
- 若用户套模板/交付时不需要该清单，也必须在本地工作目录留存，不丢弃。

## 3 · 与既有规则衔接

- 配图下限、图注格式（图 N｜标题｜来源）、docx 体积控制（长边 ≤1000px、JPEG 85）、界面图选项 A/B 均沿用 `image-engine.md`，不变；**界面图默认选项改为 B（v1.3 结论）**。
- 交互审核中用户回复"2"（图片重新生成）时，回到本文件第 1、2 节重跑（先补搜网图，再重生成 AI 图），并说明改了什么。
- 生成整本教案时，多节配图**不要求全局风格统一**（铁律 2）：按每节知识内容选类型风格，同类型内部保持一致即可。
